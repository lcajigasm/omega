# Analysis, 19 Nov 2026: disk limits, configuration assistants, MCP, help

Base: `main` at `a4d94e8` (formula for v0.29.0).

## What the run logs and one real machine show

The 30 run logs of a developer Mac (228 GB disk) between 16 and 19 November
went from ~99 GB free to 40 GB free in three days. omega's own runs found the
causes each time, and each time had to leave most of it to the user:

| Where | Size | Who owns it | Does the tool limit it? |
|---|---|---|---|
| git worktrees `wt-*` of one repository | ~30 GB (18 × 1.7 GB) | the user | no tool owns them |
| Claude Desktop `vm_bundles` (Cowork VM image) | 11–13 GB | Claude Desktop | no setting; downloaded again when missing |
| Cursor `globalStorage/anysphere.cursor-agent-worker` | 4.1 GB | Cursor | no: 7 versions of its agent kept, 1 used, plus the archives |
| `~/.local/share/cursor-agent/versions` | 1.2 GB | cursor-agent installer | no: 2 versions, 1 used |
| Docker Desktop disk image | 2.4 GB | Docker | yes: `DiskSizeMiB`, `builder.gc`, log rotation |
| `~/.codex` | 1.4 GB | Codex / ChatGPT app | partly: `[history] max_bytes`; sessions never trimmed |
| `~/.claude/projects` | 220 MB | Claude Code | yes: `cleanupPeriodDays` (30 by default) |
| Homebrew downloads | varies | Homebrew | yes: `HOMEBREW_CLEANUP_MAX_AGE_DAYS` (120 by default) |

The logs also show the agent improvising `du`, `find` and `sed` on these
folders run after run, and stopping at "close Claude and delete it yourself".

## Chosen

1. **One catalogue of tools, each with checks** (`internal/assist`). A check
   is a *setting* the tool documents (written in its own file, after a copy is
   kept in `~/.local/state/omega/backups/`), a *budget* omega keeps for a
   folder the tool never trims, a *cleanup* that loses nothing (old versions,
   caches), an *action* (deny rules, MCP registration) or *info*. The disk
   limits are the checks marked disk; the configuration assistants are all of
   a tool's checks. One code path serves the command, the app and the MCP
   server.
2. **Settings, not deletions, where the tool has one.** Docker's build cache
   and log rotation in `~/.docker/daemon.json`, Docker Desktop's disk size in
   `settings-store.json` (never below what it holds), Claude Code's
   `cleanupPeriodDays`, Codex's `[history] max_bytes`, Homebrew's
   `brew.env`. JSON keeps order and every key omega does not set, through
   sjson; a file with comments is refused. TOML is edited line by line and
   must parse before and after.
3. **Budgets are the user's number.** omega never picks a size for Claude's VM
   image or DerivedData; `omega disk limits set <check> 8GB` stores it in
   `config.toml` and `omega disk limits enforce` keeps it, skipping any app that
   is open. Conversations and sessions lose their oldest files first; caches
   and images are emptied.
4. **Old versions are found by their link.** Every version folder but the one
   `~/.local/bin/<tool>` (or Cursor's own link) points into goes; with no link,
   the newest stays.
5. **Assistants for Claude Code, Claude Desktop, ChatGPT/Codex, Grok, Docker,
   Cursor, VS Code, Gemini CLI, Homebrew, Xcode and Ollama.** Beyond disk:
   deny rules that keep Claude Code out of `.env`, SSH and AWS keys and
   omega's own configuration, and registering omega's MCP server in each agent
   that can use one. On this machine "ChatGPT.app" is the Codex app (bundle
   `com.openai.codex`) and shares `~/.codex` with the CLI, so they are one
   assistant. Grok Bot keeps no configuration omega can read; its assistant is
   its caches.
6. **`omega mcp`.** An MCP server on stdio with twelve tools. Each runs the
   omega command a person would type, with no terminal; arguments are plain
   words. Read-only tools are annotated so; settings keep a copy; the one
   tool that deletes (`omega_free_space`) is annotated destructive and only
   lists unless `dry_run` is false. There is no tool for a task, the model
   loop or an arbitrary command.
7. **Help.** `omega --help` groups the commands by purpose and ends with how
   to ask; `omega docs` embeds the manual (offline search with a few words of
   Spanish, French and German mapped to English); `omega docs ask` answers from
   the manual with the configured model in the user's language; `omega man`
   writes every command with its options and examples.

## Left out

- **Git worktrees** are the biggest item and belong to the user; `omega git`
  is where they fit, not a tool's limit.
- **Cursor's own `workspaceStorage` and `state.vscdb`**: databases an open
  editor writes; no safe trim from outside.
- **Gemini CLI's `sessionRetention`**: not set until its key is confirmed in
  the version people run.
- **Scheduling `enforce`**: `omega schedule` runs tasks; until it learns to run
  commands, `omega disk limits enforce --yes` goes in cron or launchd.
- The checks' own texts are English in every language for now; the app's
  frame around them is translated.
