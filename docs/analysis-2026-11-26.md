# Analysis, 26 Nov 2026: why disk cleanup falls short, and omega ultra

Base: `main` at `e7a3b9d` (formula for v0.34.0).

## What the run logs and one real machine show

The 30 run logs in `~/.local/state/omega/runs` (23 to 26 November) and a scan
of the same Mac (228 GB disk):

- **Every run used `claude-haiku-5-5`.** Automatic mode starts on the fast
  tier and only escalates when a step fails; cleanup never fails, so the
  deepest decisions about the disk were always taken by the cheapest model.
- **Only `mo clean` freed space on its own** (6.6 GB on the 24th, 5.7 GB on
  the 26th). The ~48 GB of the interactive run on the 26th came from commands
  the model improvised: `mv` of Claude's `vm_bundles` to the Trash and
  `rm -rf ~/.Trash/*`, a chain of 16 `git worktree remove`, `docker image
  prune -a -f`.
- **That `docker image prune -a` took 2.14 GB against 824 MB measured**,
  including `omega:ci`, an image built on the machine that no registry can
  give back.
- **The worktrees are the biggest item and were never handled by omega.** Run
  after run they were reported as "uncommitted changes, left to the user".
  Today 13 `wt-*` worktrees of one repository hold 22 GB; in 7 of them the
  only "uncommitted" files are what the agent wrote (`.claude-run.json`,
  `PLAN.md`, `.pr-body.md`, `.review.diff`, `*.codex.txt`), with the branch
  already pushed. Plus 7 worktrees under `.claude/worktrees` and 21 Codex
  transcripts (`*.codex.txt`) next to the projects.
- **Unattended runs never clean what matters**: every cleanup option is rated
  `dangerous`, so nobody takes it; and options omega took automatically were
  then not carried out by the model (093157, 092934).
- **`dev-artifacts` (60 days) finds nothing while `mo purge` finds 189 MB**
  every run: the threshold is too long for agents' build folders.
- **`find` was blocked by the safety policy** while looking for git logs, and
  free space went 64 → 21 GB between two runs with nothing in the logs to say
  why: no run measures what happened between runs.

## Chosen: omega ultra

1. **Everything omega does, in one attended run.** Every stage of `omega
   full`, plus `deep` (deep clean) and `care` (every deterministic review:
   agents left running, configuration assistants, audit, privacy, network,
   skills, pending). `omega_cmd` gives the model omega's own commands instead
   of improvised `du`, `find` and `rm`.
2. **Stronger models, more effort, more turns.** Stages start on the smart
   tier with effort `high` and escalate to a new ultra tier (Anthropic: Opus);
   the deep clean starts on it. `providers.<name>.ultra_model` overrides it.
3. **A deterministic scanner, not the model, decides what is safe**
   (`internal/deepclean`): worktrees classified by what `git status` reports
   (agent files vs the user's), whether the branch is pushed, merged, recent,
   locked or in use by a running process (`lsof`); loose agent files; Docker
   images, stopped containers and volumes one by one, with images built
   locally told apart.
4. **Validated before proposed, verified before done.** `deep_inspect` gives
   the model the evidence (every file, the diff, the commits, the PR state with
   `gh`); a card whose changing options carry no evidence is refused; each
   removal is checked again just before it runs; a worktree's work is rescued
   (patch, untracked files, a branch for a lost commit) before it goes.
5. **Always the person's yes.** Approval `all`, `--yes` and `--auto` refused,
   a terminal required.

## Left out

- Fixing the unattended issues above (automatic picks not carried out,
  cleanups never taken): ultra is attended by design; they belong to
  `omega unattended`.
- Measuring what changed between runs (the 43 GB that vanished): a journal of
  free space per run would explain it.
- `dev-artifacts`' 60-day default is unchanged; ultra uses 14 days.
