macOS and Linux · free and open source

Updates that fix their own errors

omega updates and cleans your Mac or your Linux machine like topgrade and Mole, then reads every failure, finds the cause and fixes it. You pick what it does from a card and approve anything risky.

brew install lcajigasm/tap/omega
tar -xzf omega_*_linux_amd64.tar.gz sudo install -m 755 omega /usr/local/bin/omega Get the archive

Homebrew works on macOS and on Linux. Then run omega setup.

The problem

Your update script fails. Then you debug it all evening.

Running topgrade and Mole by hand

  • A step fails and the run moves on with a red line you have to scroll back to
  • You search the error, edit topgrade.toml and launch everything again
  • A package asks for a password halfway through and the run hangs
  • The same pipx failure comes back next month

Running omega

  • It reads the failure the moment it happens and works out the cause
  • It applies the smallest fix, retries once and moves on if it still fails
  • Commands run without a prompt, so nothing waits on a password you cannot see
  • It writes down what it learned and starts there next time

What it does

What changes when an agent runs your maintenance

Failures get fixed, not just reported

omega reads the output, checks the config behind it and retries with the fix. It also reads the system logs for crash loops and failing services.

You pick, it does

Recommendations arrive on a card with their impact. Tick one or several, and omega carries out exactly those. Nothing else.

Nothing risky runs without you

Every command is classified before it runs. Deletes and config edits wait for your yes, and the truly destructive commands never run.

The best value model, checked daily

omega reads current prices and benchmark scores once a day and picks a fast model for routine work and a stronger one for failures.

Tunes your tools with current docs

omega tune reviews the config of what you have installed, reads the official documentation and proposes improvements with their source.

Your toolchain, installed and in order

omega dev knows more than 70 languages, version managers and command-line tools. It installs what you pick and finds what overlaps.

Docker back under control

omega docker shows what images, volumes and build cache take, and cleans only what you tick. Docker cleanups always ask first.

A menu for everything

omega menu lists every command, with its options and settings to pick from. Type a few letters to find anything.

Ask in words

Type omega why is my disk full, or "undo yesterday's Dock change" inside a session. What the command line does, the agent can do too.

Getting started

Running in three commands

  1. Connect a model

    The setup asks for your provider, stores the key in the macOS Keychain or the Linux keyring, and lets you pick a model.

    omega setup

  2. Get a report first

    Analyze is read only. You see disk usage, outdated software and config problems before anything changes.

    omega analyze

  3. Let it do the maintenance

    Updates, cleanup and a summary, with your approval on anything risky. Or open the menu and pick.

    omega
omega menu

Platforms

It knows the system it runs on

The same agent, with each system's own steps. On a Mac it also reviews what runs outside the apps you open.

macOS

Apps add themselves to login, keep helpers running in the background, grab shortcuts other apps already use and leave permissions and files behind when they go. omega mac reviews all of it, asks you on cards and applies only what you pick. Every change can be undone.

login
Apps that open at login: updaters and apps you open when needed go, VPN, security and sync stay
background
Launch agents, daemons and app helpers, including leftovers of uninstalled apps
menubar
Menu bar apps: quit them, stop them at login, or hide them with Bartender, Ice or Thaw
dock
Apps no longer installed or not opened in 90 days, and the Dock settings you prefer
shortcuts
Who keeps each contested shortcut; the others move to a free one
permissions
Privacy & Security entries whose binary or app is gone, each named with its version so the copies can be told apart
apps
Apps not opened in 180 days, apps built only for Intel, and what removed apps left in ~/Library

Linux

On Debian, Ubuntu, Fedora, Arch, openSUSE and their relatives, omega knows which distribution it runs on and uses its package manager. The steps that need sudo wait for your approval and ask for the password inside the interface.

packages
Check, update and clean with apt, dnf, pacman or zypper, including orphaned packages and the package cache
flatpak, snap
Updates, unused runtimes and old snap revisions
journal, disk
Failed units, errors since boot, core dumps, the size of the journal, ~/.cache and the Trash
keys
In the system keyring (GNOME Keyring, KWallet) or, on a server with none, in a file only you can read. omega says which
homebrew
With Homebrew on Linux, the brew steps work as they do on a Mac
  • The Mac review (omega mac) and the Mac-only steps do not exist on Linux, and say so
  • Without apt, dnf, pacman or zypper (Alpine, NixOS, Void) the system-package steps do not appear
  • Immutable systems such as Fedora Silverblue are not adapted yet
  • Windows is not supported: the binaries start, but there are no Windows steps

Developer tools

Languages and version managers pile up: two of them managing Node, a command that resolves to the wrong copy, a PATH entry that points nowhere. omega dev shows what is installed and who installed it, and fixes what you pick. On both systems.

dev status
What is installed, by which manager, and what stands out: overlapping version managers, shadowed commands, a broken PATH, shell startup time
dev install
Pick from a card or name the tools: more than 70 languages, version managers and command-line tools, installed with Homebrew or your distribution's packages
dev activate
Adds the line a tool needs to ~/.zshrc, or ~/.bashrc for bash, after saving a copy of the file
dev
The guided review: the agent reads the inventory, explains each finding and applies what you approve

Safety

Four risk levels. You decide on the ones that matter.

Compound commands are split and checked part by part, through wrappers such as env, sudo and sh -c. The highest risk wins.

Read only

Runs straight away

brew outdateddf -hapt list --upgradable

Normal

Runs straight away

brew upgradenpm update -grustup update

Dangerous

Waits for your approval. Docker cleanups ask every time

rmsudodocker … prune

Blocked

Never runs, even with --yes

rm -rf ~diskutil erasecurl … | sh

  • The agent cannot read your API keys: not from the keychain, a key file or an environment variable
  • It cannot change the provider or lower its own approval policy
  • Commands run with stdin closed, so nothing hangs on a hidden prompt
  • Config edits show a diff and keep a timestamped backup
  • Every run is logged, including what you approved and denied
  • Changes to your Mac are recorded and can be undone one by one

Models

The model you trust, at the size the job needs

Automatic by default: a fast model for routine work, a stronger one when something fails. Pin any model with omega model, or switch mid-run with ctrl p.

Picked from live data, once a day

omega reads public list prices and benchmark scores, keeps the models your key can use and picks two.

  • Fast, for routine work: the best score per dollar among models with at least 40% of the best score. Price weighs most.
  • Smart, when a step fails: the best value among models within 20% of the best score. Score weighs most.
  • A pick changes only when another model beats it by more than 10%, so two close models do not alternate.
  • omega models shows the table. omega config set model_catalog off stops the download.

FAQ

Questions

Does omega replace topgrade and Mole?

For a typical developer machine, yes. omega has its own steps for Homebrew, the Mac App Store and macOS on a Mac, for apt, dnf, pacman, zypper, Flatpak and snap on Linux, and on both for npm, pnpm, bun, pipx, uv, rustup, cargo, gh extensions, Oh My Zsh, caches, Docker and the Trash. If topgrade or Mole are installed, it also uses them and can fix their configuration with omega fix.

What does omega send to the AI provider?

Its instructions, the trimmed output of the commands it runs and the configuration files it reads. It is instructed never to open your documents. Every run is logged to ~/.local/state/omega/runs. omega logs lists those transcripts and omega logs view prints one. omega keeps the newest 30.

A command from this page says it does not exist. Why?

Your omega is older than this page, which describes the latest release: omega dev and omega menu, for example, arrived in 0.14.0. Run brew update && brew upgrade omega, then omega --version. omega doctor tells you when a newer release exists.

What does omega doctor check?

Whether a newer release exists, the config file, whether the API key looks like a key, whether the provider answers, and which maintenance steps are installed. It also reports the two models automatic mode will use. It lists models or probes a local server and never sends a chat message, so it does not spend tokens.

Can omega delete my files?

Only after you approve it. Deleting, sudo, editing config files and any unknown command need your confirmation. Commands like rm -rf ~ or rm -rf / (extra flags still count), diskutil erase or curl piped into a shell are blocked and never run, even with --yes.

Which AI models work with omega?

Any model with tool calling from Anthropic, OpenAI, OpenRouter or OpenCode Zen, or a local one through Ollama, LM Studio or any OpenAI compatible endpoint. By default omega uses a fast model and switches to a stronger one when a step fails. Choose with omega model.

How does omega choose the model?

From live data, not from a list built into the program. Once a day it reads OpenRouter's public model catalogue, which carries list prices and the Artificial Analysis index, keeps the models your key can use and picks two: the fast one by score per dollar among models with at least 40% of the best score, and the smart one among models within 20% of the best. omega models shows the table and the picks. The request carries nothing about you, and omega config set model_catalog off stops it. The score is a general benchmark, not a test of maintenance work.

Can I change the mode or the model during a run?

Yes. shift tab cycles between asking before risky actions, auto approve and read only, and ctrl p switches to the next model of the run. Press ? for the shortcut card. In the input box, type / for commands such as /mode, /model and /exit: a menu explains each one as you type. A model you pick by hand is kept for the rest of the run. The first esc clears a line you have started; the next one ends the session. ctrl f searches the transcript: Enter jumps to the next match and Ctrl+P to the previous while search is open. ctrl y copies the focused tool output. Click a card row to select it, and click the key line to confirm.

How much does a run cost?

On the automatic model a typical run costs under one cent: a full configuration review on a real Mac came to $0.009. omega shows tokens and cost live in the status bar and in the final summary. Local models cost nothing.

Can it run on a local model?

Yes. Start Ollama or the LM Studio server and pick the provider in omega setup. Apple Intelligence's on device model is only reachable from Swift and its 4,096 token context is too small for this kind of agent, so omega uses local servers instead.

How does omega tune know the right settings?

It does not ship a fixed list. For each tool you have installed it gets pointers to the config files and the official docs, reads the current documentation on the web, and proposes changes with their source. You pick which ones to apply, or use --auto for the low risk ones.

Can omega run unattended?

Yes. Run omega update --yes --no-tui --once from launchd or cron. Blocked commands stay blocked, Docker is never cleaned without you, and recommendations go into the summary instead of a card.

What happens when something needs admin access?

Commands run detached from your terminal, so nothing can write over the interface. When a tool such as Mole or softwareupdate asks for sudo, omega shows a password card, checks the password with sudo and keeps it in memory for that run only. It is never logged or sent to the AI. Press Esc to skip the steps that need it.

Does omega work on Linux?

Yes. On Linux omega checks, updates and cleans through apt, dnf, pacman, zypper, Flatpak, snap and Homebrew, reviews the systemd journal, keeps API keys in the system keyring or in a file only you can read, and installs developer tools with your distribution's packages. omega mac (login items, menu bar, Dock, shortcuts, privacy permissions, apps) and the Mac only steps do not exist on Linux. Windows binaries are published, but Windows is not supported.

Does omega work on Windows?

No. Each release includes Windows binaries that start and show the interface, but there are no Windows maintenance steps and no key storage, so Windows is not supported. Under WSL, omega is the Linux version.

Can omega sort out login items, the menu bar and shortcut conflicts?

Yes, with omega mac. It lists what opens at login, what is allowed in the background, menu bar apps, the Dock and global keyboard shortcuts, and suggests changes from your rules (~/.config/omega/mac.toml) and its defaults: updaters off, chat and AI assistants opened when needed, VPN, security and sync kept, and AI assistants that grab a shortcut on install moved to a free one. Your choices are saved for next time, and omega mac undo reverts any change.

Can omega clean the list of privacy permissions?

Yes, with omega mac permissions. It finds the entries in System Settings → Privacy & Security whose binary no longer exists (an app that bundles node in a versioned folder leaves one per update) or whose app is gone, names each with its version, and removes the ones you pick after saving a copy of the database. Reading your own list needs Full Disk Access for the terminal. Entries macOS protects system-wide, such as Full Disk Access, Accessibility and Screen Recording, are found but have to be removed by you in System Settings.

Can omega install and set up my developer tools?

Yes, with omega dev. It knows more than 70 languages, version managers and command-line tools. omega dev status shows what is installed and by which manager, and points out overlapping version managers, commands that resolve to the wrong copy and PATH entries that do not exist. omega dev install installs what you pick and omega dev activate adds the shell line a tool needs to ~/.zshrc, keeping a copy of the file.

Can I just tell it what I want?

Yes. In a session, type what you need: "install fzf and mise", "undo yesterday's Dock change", "what failed last time?", "which model should I use?". The agent can install tools, revert Mac changes, read earlier runs, manage its notes, change settings and run the setup check, asking before each change. It cannot read your API keys, change the provider or change the approval policy: for those it gives you the command.

Where are my API keys stored?

In the macOS Keychain, under the service omega-cli. On Linux, in the system keyring (Secret Service) when one answers, otherwise in ~/.config/omega/keys, a file only you can read; omega says which one it used. Environment variables such as ANTHROPIC_API_KEY take precedence when set.

Which languages does the interface support?

English, Spanish, French, German and Portuguese. omega follows your system locale, and you can override it with omega config set language. The agent replies in the same language.

Install

Start with a report that changes nothing

Free and open source under the MIT license. omega analyze is read only, so you can see what it would do before you let it do anything.

Homebrew, on macOS and Linux

brew install lcajigasm/tap/omega
omega setup
omega analyze

Update later with brew update && brew upgrade omega. The previous tap, lcajigasm/omega/omega, still works.

Linux without Homebrew

tar -xzf omega_*_linux_amd64.tar.gz   # or linux_arm64
sha256sum -c SHA256SUMS --ignore-missing
sudo install -m 755 omega /usr/local/bin/omega

Every release has archives for macOS and Linux, amd64 and arm64, with checksums. Windows archives are published too, but Windows is not supported.
